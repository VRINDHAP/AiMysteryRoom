# AI Mystery Room

AI Mystery Room is a fictional detective game. Create a case from a story idea, inspect its suspects and evidence, then make one final accusation. The backend keeps the culprit and solution private until the accusation is submitted.

All people, events, messages, and evidence generated by the app are fictional.

## Features

- Generate a case with Google Gemini from a custom scenario.
- Choose a case category, difficulty, and suspect count.
- Explore suspect profiles, evidence, and the case timeline.
- Filter and bookmark evidence, and keep investigation notes.
- Submit one accusation and reveal the case solution.
- Save cases and investigation sessions in MongoDB.

## Tech stack

- Frontend: React, Vite, React Router
- Backend: Node.js, Express
- Database: MongoDB with Mongoose
- AI: Google Gemini API through the backend
- Validation: Zod

## Requirements

- Node.js 20 or later and npm
- MongoDB locally or a MongoDB Atlas connection string
- A Google Gemini API key

## Local setup

1. Create a `.env` file from the example:

   ```powershell
   Copy-Item .env.example .env
   ```

2. Set the values in `.env`:

   ```dotenv
   PORT=4000
   MONGODB_URI=mongodb://127.0.0.1:27017/ai-mystery-room
   GEMINI_API_KEY=your-gemini-api-key
   GEMINI_MODEL=gemini-2.5-flash
   CLIENT_ORIGIN=http://localhost:5173
   ```

   Keep `.env` private. The Gemini API key is only used by the backend.

3. Install dependencies and start the frontend and API:

   ```bash
   npm install
   npm run dev
   ```

4. Open `http://localhost:5173`.

Vite proxies `/api` requests to the Express API on port 4000. MongoDB and a valid Gemini key are required to generate cases. If Gemini is not configured, generation displays a setup error instead of creating a hardcoded case.

## Available scripts

| Command | Description |
| --- | --- |
| `npm run dev` | Start the Vite frontend and Express API together |
| `npm run dev:client` | Start only the frontend |
| `npm run dev:server` | Start only the API with automatic restarts |
| `npm run build` | Build the frontend into `dist/` |
| `npm start` | Start the API server |

## API routes

All application routes use the `/api/v1` prefix.

| Method | Route | Description |
| --- | --- | --- |
| `POST` | `/mysteries/generate` | Validate input and generate a case |
| `GET` | `/mysteries/:id` | Get public case data without the solution |
| `GET` | `/mysteries/:id/evidence` | List evidence; supports `category`, `type`, and `suspectId` filters |
| `PATCH` | `/sessions/:sessionId` | Save viewed evidence, bookmarks, and notes |
| `POST` | `/mysteries/:id/accusation` | Submit the final accusation and return the solution |
| `GET` | `/mysteries/:id/result/:sessionId` | Retrieve the result after an accusation |

Guest session IDs are random UUIDs stored in the browser's local storage. Accusations cannot be submitted twice.

## Production deployment

Build the frontend with `npm run build` and deploy the generated `dist/` directory to a static host. Deploy the Express API to a Node.js host. Configure `MONGODB_URI`, `GEMINI_API_KEY`, `GEMINI_MODEL`, and `CLIENT_ORIGIN` in the API host's environment. Set `CLIENT_ORIGIN` to the deployed frontend origin.
